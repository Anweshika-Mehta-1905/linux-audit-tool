How it works
From zero to audit in 3 commands

No installs, no Python, no external packages. The script uses only tools that already exist on every Linux system.

1
Create the script file
Open a terminal and paste the script into nano, a built-in text editor. No downloads needed.
2
Make it executable
Tell Linux this file is a program it can run, not just a text document.
3
Run the audit
Execute the script. It scans your system across 6 modules and shows color-coded results.
4
Save a report
Export the findings to a plain text file to keep, share, or add to your portfolio.
admin123@ubuntu: ~
# Open the script file in nano text editor
$ nano ~/linux_audit.sh

Sample findings
What the output looks like

Findings are automatically colour-coded by severity. Here are real examples from an Ubuntu 26.04 scan.

CRITICAL
🔓
/etc/shadow is readable
The shadow file holds hashed passwords for every user. If readable, an attacker can run offline cracking tools like hashcat to recover them.
stat /etc/shadow → should be: -rw-r----- root:shadow
CRITICAL
⚡
SUID binary: vim (GTFOBins match)
vim with the SUID bit set lets any local user open a root shell by typing :!/bin/sh inside the editor. A textbook privilege escalation path.
find / -perm -4000 -name vim 2>/dev/null
CRITICAL
🦠
Process running from /tmp
An executable was launched from /tmp — a common sign of malware staging, post-exploitation tooling, or a dropper that hasn't cleaned up yet.
PID 4821 → /tmp/audit_sleep (uid 1000)
REVIEW
🔑
Passwordless sudo access
sudo -n -l succeeded without requiring a password. This means the current user can run privileged commands silently. Verify the scope is intentionally limited.
sudo -n -l → (ALL) NOPASSWD: ALL
REVIEW
📋
SUID binary: /usr/bin/passwd
Standard system binary. SUID is expected here so users can change their own password. Listed for baseline documentation and change tracking.
-rwsr-xr-x root:root /usr/bin/passwd
PASSED
✅
$PATH is clean
No dot (.), relative paths, or world-writable directories were found in $PATH. This means PATH hijacking attacks cannot be performed via this vector.
$PATH → /usr/local/sbin:/usr/local/bin:...
Get started
Up and running in 3 steps

No package manager, no internet connection required during the scan. Just a terminal and the script.

1
Open a terminal
In Ubuntu, press Ctrl + Alt + T to open a terminal window. Then type the command below to create the script file.
nano ~/linux_audit.sh
2
Make it executable
After saving the script, run chmod to give it execute permission. The +x flag means "make this runnable".
chmod +x ~/linux_audit.sh
3
Run the audit
Execute the script. The 2>&1 | less -R part keeps the colours and lets you scroll through the output.
~/linux_audit.sh 2>&1 | less -R
4
Save a report file
Export the results as a text file for documentation, portfolio use, or sharing with a team.
~/linux_audit.sh --no-color > report.txt
